## 1. 为什么需要这份文档

本仓库 fork 自个人项目 **Genote**（面向考研 / 考公学生的 AI 学习助手），团队比赛选题是 **校园 AI 知识库助手**。两者产品方向不同，直接沿用会造成三处不一致：

1. 申报材料写的产品与实际代码 / 原型展示的产品对不上；
2. 原型里的考研倒计时、付费订阅等 C 端设计被误当作比赛版范围；
3. 技术底座（Open Notebook 自托管）与决策记录的云架构冲突，评审追问时无法解释。

因此本文件明确：哪些资产复用、哪些需要改造、哪些不进入比赛 MVP，以及与本仓库外的工作空间仓库如何分工。

## 3. 方向差异对照

| 维度 | Genote 原产品 | 比赛版（决策） |
|---|---|---|
| 产品定位 | 考研 / 考公 AI 学习助手 SaaS | 通用校园 AI 知识库助手 |
| 核心场景 | 长时学习、超大 PDF、长视频问答、笔记复习 | 办公辅助 + 来源整理成知识库 + RAG 提取 + 按内容生成；生涯规划为模块 |
| 目标用户 | 备考学生 | 大一大二学生（生涯规划模块）与校园用户（知识库与办公） |
| 数据来源 | 用户自行上传的备考资料 | 五类基础数据（培养方案 Excel、竞赛目录 + 素拓认定、就业质量报告、学生手册 / FAQ、行业真相卡素材）等授权材料 |
| 技术底座 | Open Notebook：Next.js + FastAPI + SurrealDB + Docker Compose | Next.js（Vercel）+ Supabase（Postgres、pgvector、Auth、私有 Storage、Queues）+ Python Deep Agents / LangGraph + Freestyle VM |
| 商业模式 | 月度订阅 15–25 RMB | 比赛 MVP 不做商业化验证 |
| 交付形态 | Web 产品原型 | 24 天 MVP + 5–8 分钟真实运行演示 + 申报书 |

## 5. 需要改造

| 对象 | 原状 | 改造方向 |
|---|---|---|
| 首页与入口 | 考研倒计时 + 每日签到 | 校园学习 / 资料场景；倒计时与打卡降级为可选激励 |
| 用户与权限 | 单一用户、无登录 | Supabase Auth；按项目 / 工作区隔离数据 |
| 知识来源 | 用户上传 PDF / 视频 | 增加培养方案、竞赛目录、就业质量报告、学生手册 / FAQ 等授权材料的导入与解析 |
| 问答范围 | 自由问答 | 只用所选资料 + 引用；不可控信息明确说明 |
| 生成能力 | 笔记 / 闪卡 | 学习 Studio：笔记、闪卡、测验、讲义、思维导图；办公交付：DOCX / XLSX / PPTX / PDF |
| 技术底座 | FastAPI + SurrealDB + Docker | 按决策改 Next.js（Vercel）+ Supabase + Deep Agents / LangGraph + Freestyle VM |
| 生涯规划 | 原型中没有 | 按方案一 v2 三段式探索漏斗新增模块（看清牌面 → 试算方向 → 落地路径） |
| 产品名与文案 | Genote / 考研 / 考公 | 比赛版对外名称待定；文档与界面不出现付费、考研倒计时等与比赛范围无关的表述 |

## 6. 比赛 MVP 不采用或暂缓

| 项 | 处理 | 理由 |
|---|---|---|
| 考研 / 考公 C 端定位 | 不采用 | 比赛选题为校园 AI 知识库助手 |
| 月度订阅 / Stripe 计费 | 暂缓 | MVP 不做商业化验证 |
| Dify workflow DSL、`Genote_beta_*.yml` | 不采用 | 原方案已废弃，仓库内无对应文件；决策采用 Deep Agents / LangGraph |
| Docker Compose 自托管 | 不作为正式部署 | 决策采用 Vercel + Supabase + Freestyle VM |
| 播客生成、内容转换等扩展 | 暂缓（非否决） | 不进入 24 天 MVP，保留为演示后的延伸 |
| 本地存储 / 游客模式 | 不采用 | 已被 2026-10-15 会后修订的云架构取代 |
| 移动端原生 App、离线模式、协作编辑 | 不做 | 原 PRD 即标注为范围外 / 未定 |

## 10. 维护规则

1. 本文档随团队决策变化更新，不删除历史结论；被取代的条目写明取代者。
2. 修改通过 `docs/` 分支 + PR 合并，由非作者评审（参照工作空间仓库规则）。
3. 不写入未核验的统计数字、未授权的数据来源或真实的个人信息。
4. 与 `decision.md` 出现分歧时，先改本文档，再在团队会议中同步。

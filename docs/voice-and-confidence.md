# 表达层（Voice & Confidence）产品规范

> 状态：2026-11-05 生效。适用于**所有面向用户的产品文案**：资料库问答、五步向导、方案页、导出 PDF、
> 空态/提示/免责声明，以及 worker 里所有模型提示词与确定性兜底文案。
> 依据：团队 2026-11-05 反馈（吴迪仪：来源数据都来自官网，资料库每条后面不要再挂「待核验／部分核验」；
> 整个产品不要"过分谨慎"的语气），并采用 [no-ai-slop](https://github.com/petergyang/no-ai-slop) 的编辑规则去 AI 味。

## 1. 为什么要改

产品原来的写法是「防御式写作」：每条来源后挂核验状态、每段结论后补一句免责、每个缺口都写成
"资料不足／待核验"。它保护了团队，却让用户读到的是**不确定**。知途卖的是"我现在该做什么"，
用户需要的是一个敢下判断、能立刻执行的方案。

本次调整只改**怎么说**，不改**事实从哪来**：数字仍然只能来自规则引擎与证据，引用编号仍然可回溯。
自信不等于编造——「可信赖」= 确定 + 可回溯。

## 2. 表达契约（写进每个 system prompt，作为硬约束）

1. **结论先行**：第一句直接给判断/答案。不铺垫、不复述问题、不自我介绍。
2. **确定语气**：用「是／可以／优先／先做／到这里查」这类明确动词。已归档资料视为团队已核对资产，
   直接陈述；不再逐条标注「待核验／部分核验／未核验」。
3. **依据紧随**：结论后给依据，事实句带 `[n]` 引用；引用编号只能来自本次证据。
4. **适用范围只说一次**：文末一行「适用范围：……」交代届别/口径/时点，一句话结束。
   禁止把它写成缺陷清单（"资料不足""覆盖不均衡""数量有限，不能外推"）。
5. **具体**：写清楚对象、时间、入口、动作、判断标准。禁止「进一步了解」「持续提升」「综合考虑」空话。
6. **去 AI 味**：禁用词与禁用句式见第 4 节；同一段不重复同一句式；不用 emoji、不用装饰性加粗。
7. **不编造**：没有证据的数字、来源、结论一律不写；改用"到哪个入口可以拿到这个数"的明确路径。

## 3. 各场景落点

| 场景 | 改法 |
|---|---|
| 资料库「来源查看」列表 | 每条只留标题（有官方链接就成了链接），删掉 `<span class="source-line-meta">待核验</span>` |
| 引用卡 / 悬停气泡 | 不显示核验 badge；网页来源只标「实时网页」，不写「未核验」 |
| 方案页课程/竞赛线索 | 不挂核验 badge；「待核验资料」折叠改成「下一步核对」 |
| 导出页 | 「待核验项」折叠改成「下一步核对」；不出现「待核验」badge |
| 知识图谱 | 状态文案改为「已收录／官方来源／参考线索」，删「待核验／未核验」；「只看已核验」筛选改为「只看官方来源」 |
| PDF | 章标题「六、课程与竞赛」「十二、下一步核对」；去掉「核验状态」列与「待核验行动」字样；免责声明压到一段、正面表述 |
| 问答兜底 | 不再输出「资料不足，无法回答」；改为：先给资料库覆盖范围内能确定的部分，再给"到哪查"的具体路径 |
| 计划兜底 | 不再输出「AI 解释未通过校验」「资料不足以生成…」；改为该方案已有的确定事实摘要 + 下一步 |

## 4. 禁用表达（提示词 + 后处理 + 前端文案共用）

**禁用词**（inflated / AI 腔）：
深入、赋能、助力、全方位、多维度、一站式、无缝、颠覆、革新、范式、生态、闭环、抓手、底层逻辑、
降维打击、极致、王炸、重磅、里程碑、划时代、至关重要、意义深远、彰显、凸显、体现…的承诺/决心。

**禁用句式**：
- 二元对比："不是 X，而是 Y" / "并非 X，而是 Y" / "不仅 X，更是 Y"
- 铺垫开场："需要说明的是""值得一提的是""需要指出的是""客观来说""从某种意义上说""众所周知"
- 伪洞察："很多人不知道的是""大多数人都忽略了""真正关键的是""这个问题的本质是"
- 总结回扣："综上所述""总而言之""总的来说""归根结底"
- 自我削弱："资料不足""缺少相关数据""待进一步核验""待核验""部分核验""未核验""仅供参考""样本有限""不能外推"
- 空泛建议："进一步了解""持续提升""综合考虑""多方了解""结合自身情况"
- 元评论："值得注意的是""这一点很重要""正如你所见""换句话说"（重复时）
- 破折号堆叠、emoji 标题、句中小标题式加粗。

## 5. 信任条款（保留但只说一次）

需要提醒的只有一件事：**最终行政认定以学校当年文件为准**。它出现在 PDF 末尾一段、方案页「适用范围」一行，
不重复、不逐条、不使用"不构成…"的否定式排比。

## 6. 验收

- `rg "待核验|部分核验|未核验|资料不足|缺少相关数据|条件不足" src worker/app` 只允许出现在
  内部注释、数据契约字段名、测试样例中，不允许出现在用户可见字符串。
- `worker/tests/test_voice.py`：对所有确定性兜底文案跑 `find_hedges()`，必须为空。
- 前端 `npm run check`、worker `uv run pytest -q` 全绿。
- 浏览器实测：资料库问答 → 5 步向导 → 生成方案 → 下载 PDF，页面与 PDF 中无「待核验」字样，
  语气为确定态。
